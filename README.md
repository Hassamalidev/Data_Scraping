# Canadian Halal & Muslim-Owned Business Directory

Collects publicly listed, self-identified halal-certified and Muslim-owned businesses in Canada
from trustworthy sources, cleans and de-duplicates them, stores them with full provenance, and
serves them through a website with a live dashboard, directory, map and CSV export.

The full build spec and working rules are in [CLAUDE.md](CLAUDE.md). The project is built phase
by phase (CLAUDE.md §9).

## Build status

| Phase | Scope | Status |
|---|---|---|
| 0 | Scaffold: monorepo, Docker Compose, dbmate, tooling | Done |
| 1 | Database schema, source registry, Drizzle types | Done |
| 2 | Polite fetch core (robots.txt, rate limit, retries, conditional GET, raw archive) | Done |
| 3 | Source inspection ([docs/sources.md](docs/sources.md)) | Done, awaiting source decisions |
| 4 | Source adapters | Not started |
| 5 | Normalize / geocode / dedupe / merge pipeline | Not started |
| 6 | CSV export, events, worker | Not started |
| 7–10 | Website, real-time, admin, hardening | Not started |

## Layout

```
db/migrations/   dbmate SQL migrations (single source of truth for the schema)
scraper/         Python 3.12 scraper/ETL worker (`mbd` CLI), managed with uv
web/             Next.js website (App Router, TypeScript, Tailwind)
exports/         daily CSV snapshots (gitignored)
data/raw/        raw HTML/JSON saved per source per run (gitignored)
```

## Prerequisites

- Docker Desktop (Compose v2)
- [uv](https://docs.astral.sh/uv/) (installs Python 3.12 for the scraper)
- Node.js 20.9+ and pnpm

## Setup

```sh
cp .env.example .env          # then edit; never commit .env
docker compose up -d --wait db
docker compose run --rm dbmate up
```

If port 5432 is already in use on your machine, set `DB_PORT` in `.env` to a free port and
update `DATABASE_URL` / `DATABASE_URL_DIRECT` to match.

## Database migrations

Migrations are plain SQL files in `db/migrations/`, applied with
[dbmate](https://github.com/amacneil/dbmate), which runs as a one-shot Compose service so
nothing needs to be installed locally.

```sh
docker compose run --rm dbmate up        # apply pending migrations
docker compose run --rm dbmate down      # roll back the latest migration
docker compose run --rm dbmate status    # list applied / pending
docker compose run --rm dbmate new name  # create a new migration file
```

`db/schema.sql` is regenerated by dbmate after every migration and is committed.

The website's TypeScript types are introspected from the live database, never hand-written.
After changing a migration, refresh them:

```sh
cd web
pnpm db:pull      # rewrites src/lib/drizzle/schema.ts and relations.ts
```

`db/migrations/002_sources.sql` seeds the `sources` registry only. Business rows are never
seeded; they come exclusively from scrape runs.

## Scraper

```sh
cd scraper
uv sync
uv run python -m mbd --help
uv run python -m pytest
uv run ruff check .
uv run black --check .
```

`uv run mbd ...` works too. On Windows machines where an Application Control policy blocks
the generated `mbd.exe` / `pytest.exe` launchers, use the `python -m` form shown above.

### Inspecting a source

Before any adapter is written, the source is inspected through the same polite client the
scraper uses (robots.txt check, rate limit, identifying User-Agent):

```sh
uv run python -m mbd inspect https://hiccanada.ca/certified/ --source hicc_bc
uv run python -m mbd inspect https://hiccanada.ca/certified/ --source hicc_bc --fixture certified.html
```

`--fixture` saves the page to `scraper/tests/fixtures/<source>/`. Findings go in
[docs/sources.md](docs/sources.md). Do not commit fixtures that contain personal data or that
come from a site whose terms forbid redistribution.

## Web

```sh
cd web
pnpm install
pnpm dev          # http://localhost:3000
pnpm test
pnpm lint
pnpm typecheck
pnpm format:check
```

## Common tasks

A `Makefile` wraps the commands above (`make migrate`, `make test`, `make lint`).
Pre-commit hooks (ruff, black, eslint, prettier) are configured in `.pre-commit-config.yaml`:

```sh
uvx pre-commit install
```
